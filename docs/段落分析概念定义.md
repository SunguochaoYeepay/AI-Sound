# AI-Sound项目段落分析概念定义

## 核心概念

### 段落 = 对话单元

**重要定义**：智能分段后的每个段落就是一个**对话单元**

- 每个段落可能包含：
  - 纯对话
  - 纯旁白  
  - 对话 + 旁白的混合内容

### 分析流程

```
原文章节
    ↓
智能分段（SmartSegmentationService）
    ↓
段落1, 段落2, 段落3... (每个段落 = 一个对话单元)
    ↓
对每个段落进行6卡内容丰富化分析
    ↓
输出每个段落的synthesis_json
```

## 错误理解 ❌

**不要这样做**：
```
原文章节
    ↓
智能分段
    ↓
段落1, 段落2, 段落3...
    ↓
对每个段落再次进行对话分析 ← 这是错误的！
    ↓
6卡内容丰富化
    ↓
输出结果
```

## 正确理解 ✅

**应该这样做**：
```
原文章节
    ↓
智能分段
    ↓
段落1, 段落2, 段落3... (每个段落 = 对话单元)
    ↓
对每个段落直接进行6卡内容丰富化分析
    ↓
输出每个段落的synthesis_json
```

## 关键要点

1. **智能分段**：将章节分割为对话单元（段落）
2. **6卡分析**：对每个对话单元进行内容丰富化
3. **不需要**：在段落内部再次进行对话分析
4. **每个段落**：就是一个完整的对话单元

## 实际应用

- 对话单元1：`"都别碰他！" 她厉声喝止围上来的随从...` → 这是一个对话单元
- 对话单元2：`林薇迅速从随身的药囊中取出几根细长的银针...` → 这是一个对话单元
- 对话单元3：`萧景琰的马车平稳行驶在长安街头...` → 这是一个对话单元

每个对话单元直接进行6卡分析，不需要再次分割。

## 字段命名规范

### 核心概念字段
- `dialogue_unit_text`: 对话单元原文（智能分段后的段落）
- `dialogue_unit_index`: 对话单元索引（段落索引）
- `dialogue_unit_id`: 对话单元ID（如：dialogue_unit_1）

### 分析结果字段
- `synthesis_plan`: 对话单元内的细分段落列表
- `total_segments`: 对话单元内的细分段落数
- `characters`: 角色列表
- `six_card_analysis`: 6卡分析结果

### 细分段落字段
- `segment_id`: 细分段落ID（在对话单元内的序号）
- `text`: 细分段落文本（对话或旁白）
- `speaker`: 说话者（角色名或"旁白"）
- `character_id`: 角色ID
- `voice_name`: 语音名称

## 注意事项

- 这个概念对于理解整个分析架构至关重要
- 避免在段落内部再次进行对话分段
- 每个段落就是一个完整的分析单元
- 6卡分析直接作用于段落级别
